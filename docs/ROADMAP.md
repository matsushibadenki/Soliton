Do not schedule automatic releases for unfinished work; signed native installers require their own distribution verification.

## Engine roles and consolidation — 2026-11-21

Use one Rust gateway and one resident inference engine. Offer a suitable execution profile when a user chooses a model and task. Show the proposed engine, required setup and evidence before an explicit switch. Keep manual selection available for reproducible experiments. This is the priority for engine organization; the measurements below still guide work within each backend.

| Current selection | Product role | Reason to keep it |
| --- | --- | --- |
| Strata | Default for packaged text inference with supported models | The DMG provisions its runtime on first launch. The bundled Gemma 3 1B path converts the local weights and serves text via llama.cpp/Metal. |
| vLLM-Apple | Advanced text profile and performance reference | Gemma 2 / MLX-LM 0.32.2 has a measured 4,096-token profile, prefill step 512 and qualified constrained retries. Track MLX LM and vLLM-Metal capabilities independently. |
| LFM3-Omni | Media understanding and Realtime voice | Media token accounting, output reservations, audio cancellation and slot ownership have their own contracts. Text chat provides continuity for the same conversation. |
| MLX SSD | Opt-in persistence profile for Gemma 2 | The reviewed worker supports restart reuse with a 512-token context. Keep its engine ID and launcher until a replacement passes the same restart, eviction and corruption tests at the target context. |

**Integration boundary.** Rust owns selection, process lifecycle, conversation history, request metrics and the common SSD store. Each adapter owns tokenization, prompt rendering, generation, native cancellation and KV serialization. Share storage code and telemetry definitions across MLX and Omni. Bind snapshots to their backend identity and format. Omni currently adds conversation and session identity. Switching engines replays eligible history through the destination adapter and accounts for its context budget. Keep Kapitsa-derived cache and timing techniques here as reusable capabilities.
